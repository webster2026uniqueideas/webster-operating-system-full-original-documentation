# Contribution Guide

**STATUS: PROPOSED.** Contributions should keep the architecture, implementation and evidence aligned.

Changes should reference affected `WEB-*` requirements, explain ownership and privilege impacts, update relevant specifications/API contracts, include tests and document platform/version limitations. Reviewers check least privilege, error behavior, accessibility, localization, dependency licensing and upgrade/recovery. Security-sensitive changes require threat review. Do not claim functionality as implemented based only on documentation or mocks. A formal code-of-conduct, review SLA and branch policy remain project decisions.
